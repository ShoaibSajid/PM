# Asana Integration Guide

## Overview
This guide explains how to use Asana for reviewing and assigning tasks generated by ChatGPT and tracked in Cursor.

## Role of Asana

In this workflow, Asana is used for:
- ✅ **Reviewing** tasks generated by ChatGPT
- ✅ **Assigning** tasks to team members
- ✅ **Setting** priorities and due dates
- ✅ **Tracking** task completion
- ✅ **Managing** team workload
- ✅ **Reporting** progress to stakeholders

## Workflow: Repository to Asana

### Step 1: Review Tasks in Repository

1. **Open Repository** in Cursor or GitHub
2. **Navigate** to `docs/tasks/` or `docs/features/`
3. **Review** newly created tasks (status: `draft`)
4. **Validate**:
   - Are descriptions clear?
   - Are acceptance criteria complete?
   - Are estimates reasonable?
   - Are dependencies identified?

### Step 2: Create Tasks in Asana

#### For Individual Tasks

1. **Open Asana** and navigate to appropriate project
2. **Create New Task**
3. **Copy from Repository**:
   - Task title (from # heading)
   - Description
   - Acceptance criteria (paste into description)
   
4. **Set Task Properties**:
   - **Assignee**: Select team member
   - **Due Date**: Set realistic deadline
   - **Priority**: High/Medium/Low (from repository)
   - **Tags**: Add relevant tags
   - **Custom Fields**: Add any project-specific fields

5. **Add Context**:
   - Link to repository file
   - Add estimated hours (from repository)
   - Note any dependencies

#### For Features (Multiple Tasks)

1. **Create Asana Project** for the feature
2. **Add Project Description**:
   - Copy feature overview from repository
   - Link to `docs/features/[feature-name].md`
   
3. **Create Sections** for phases:
   - Phase 1: Foundation
   - Phase 2: Core Features
   - Phase 3: Polish
   
4. **Create Tasks** from feature breakdown:
   - One Asana task for each repository task
   - Copy acceptance criteria
   - Set dependencies between tasks
   
5. **Set Project Timeline**:
   - Add milestones
   - Set target completion date

### Step 3: Link Tasks Back to Repository

After creating tasks in Asana:

1. **Copy Asana Task URL**
   - Click task in Asana
   - Copy URL from browser

2. **Update Repository File** (in Cursor):
   ```markdown
   **Asana Link:** https://app.asana.com/0/1234567/9876543
   **Assigned To:** John Doe
   **Status:** assigned
   **Assigned Date:** 2026-01-14
   ```

3. **Commit Update**:
   ```bash
   git commit -am "Link to Asana: task-name"
   git push
   ```

## Task Assignment Best Practices

### Consider Team Capacity
- Check team member's current workload
- Review upcoming time off
- Account for meetings and overhead
- Don't overcommit

### Set Realistic Due Dates
- Use estimates from repository
- Add buffer for unknowns
- Consider dependencies
- Account for review time

### Provide Context
In Asana task description, include:
- Link to repository file
- Why this task matters
- Who to contact for questions
- Related tasks or projects

### Define Clear Expectations
- Copy acceptance criteria from repository
- Add definition of done
- Specify quality requirements
- Note any constraints

## Synchronization: Asana ↔ Repository

### Keep Status Synchronized

| Repository Status | Asana Status | Action |
|-------------------|--------------|--------|
| draft | N/A | Not yet in Asana |
| ready | Created, unassigned | Ready to assign |
| assigned | Assigned | In Asana, assigned |
| in-progress | In Progress | Team member working |
| in-review | Waiting on Review | Under review |
| done | Completed ✓ | Finished |

### Update Flow

1. **Repository → Asana**: When status changes to "ready"
   - Create task in Asana
   - Assign to team member
   - Update repository with link

2. **Asana → Repository**: When work progresses
   - Team member works in Asana
   - Updates status in Asana
   - Updates repository file via Cursor
   - Commits changes

3. **Both**: When task completes
   - Mark complete in Asana
   - Update status to "done" in repository
   - Add completion notes
   - Commit final update

## Asana Project Structure

### Recommended Setup

#### Project: [Feature Name]
```
📋 Backlog
  - Unassigned tasks
  - Future enhancements

🎯 This Sprint
  - Current sprint tasks
  - Due this week/sprint

▶️ In Progress
  - Actively being worked
  - Assigned and started

👀 In Review
  - Awaiting review
  - Review in progress

✅ Done
  - Completed this sprint
  - Verified and closed
```

### Custom Fields (Optional)

Create custom fields for:
- **Estimate** (number): Hours from repository
- **Actual** (number): Actual hours spent
- **Story Points** (number): If using agile
- **Repository Link** (URL): Link to task file
- **Sprint** (dropdown): Which sprint
- **Category** (dropdown): Feature/Bug/Task

## Integration Tips

### Linking Between Tools

In Asana task description:
```
Repository File: /docs/tasks/implement-user-auth.md
GitHub Link: https://github.com/user/PM/blob/main/docs/tasks/implement-user-auth.md

Acceptance Criteria:
- [ ] Criterion 1
- [ ] Criterion 2
```

In repository file:
```markdown
**Asana Link:** https://app.asana.com/0/project/task
**Assigned To:** John Doe
**Due Date:** 2026-01-20
```

### Communication Flow

1. **Task Questions**: Comment in Asana task
2. **Technical Discussions**: Use repository (GitHub/Cursor)
3. **Status Updates**: Update both Asana and repository
4. **Completion**: Mark complete in Asana, update repository

### Notifications Setup

Configure Asana notifications for:
- Task assignments (immediate)
- Due date reminders (1 day before)
- Task completions (daily digest)
- Comments on your tasks (immediate)
- Project updates (daily digest)

## Common Workflows

### Workflow: Assigning a New Task

1. Review task in `docs/tasks/` (repository)
2. Create task in Asana project
3. Assign to team member with context
4. Set due date and priority
5. Copy Asana URL
6. Update repository file with URL
7. Change status to "assigned"
8. Commit changes
9. Notify team member

### Workflow: Task in Progress

1. Team member starts work
2. Updates Asana to "In Progress"
3. Opens task file in Cursor
4. Updates status to "in-progress"
5. Adds progress notes daily
6. Commits updates regularly
7. Comments in Asana on blockers

### Workflow: Task Complete

1. Team member marks complete in Asana
2. Opens task file in Cursor
3. Updates status to "done"
4. Adds completion summary
5. Notes actual vs estimated time
6. Commits final update
7. You review and approve in Asana

## Troubleshooting

### Tasks Not Syncing?
- Check that repository links are in Asana
- Verify Asana links are in repository
- Review last update timestamps
- Communicate with team

### Duplicate Tasks?
- Use consistent naming
- Search before creating
- Reference repository file names
- Use tags to categorize

### Status Confusion?
- Document status meaning
- Train team on workflow
- Use status field consistently
- Review in standups
